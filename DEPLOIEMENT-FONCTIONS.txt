BAOBABS BASKET CLUB — Déployer les fonctions serveur
====================================================

CE QU'ON SAIT
  Les quatre fonctions serveur (newsletter, confirmation de réservation,
  alerte d'inscription, aide à la rédaction) ne sont pas déployées.
  Vérifié : les quatre répondent 404 sur
  https://lmwbwasupqkvswukieav.supabase.co/functions/v1/…

  Le code est prêt depuis le début. Il est maintenant rangé aussi dans
  supabase/functions/, là où l'outil en ligne de commande va le chercher
  tout seul.

  DEUX CHEMINS EXISTENT, ils marchent tous les deux. Prenez celui que
  vous voulez — mais lisez « SI RIEN NE SE PASSE » à la fin.


CHEMIN A — LE TABLEAU DE BORD (sans rien installer)
  1. supabase.com/dashboard → votre projet → menu de gauche,
     Edge Functions.
  2. Bouton « Deploy a new function » → choisir « Via Editor ».
  3. Nom EXACT (tout en minuscules, avec les tirets) :

         envoi-newsletter

  4. Effacer tout le contenu de l'éditeur, coller tout le fichier
     supabase/functions/envoi-newsletter/index.ts
     (ou edge-function-newsletter.ts, c'est le même).
  5. Cliquer sur DEPLOY — et attendre la fin. Tant qu'on n'a pas cliqué
     Deploy, la fonction n'existe pas : elle est seulement écrite.

  Recommencer pour les trois autres si vous les voulez :
     confirmation-reservation, alerte-inscription, aide-redaction


CHEMIN B — LA LIGNE DE COMMANDE (plus sûr, tout d'un coup)
  Un terminal ouvert DANS le dossier du site, puis :

      npx supabase login
      npx supabase link --project-ref lmwbwasupqkvswukieav
      npx supabase functions deploy

  La troisième commande déploie les quatre fonctions d'un seul coup, en
  lisant supabase/functions/. Le mot de passe demandé à l'étape 2 est
  celui de la BASE DE DONNÉES (Project Settings → Database), pas celui
  de votre compte.


LES SECRETS — SANS EUX, RIEN NE PART
  Déployée ou non, une fonction sans ses secrets échoue à l'envoi. Les
  e-mails passent par Brevo :

      BREVO_API_KEY       la clé d'API de votre compte Brevo
      BBC_SENDER_EMAIL    l'adresse d'expédition, VÉRIFIÉE chez Brevo
      BBC_SENDER_NAME     facultatif — « Baobabs Basket Club »

  Où : Supabase → Edge Functions → Secrets → Add new secret.

  Ne mettez jamais ces valeurs dans un fichier du dépôt : elles n'ont
  rien à faire sur GitHub.


SI RIEN NE SE PASSE — LES CINQ CAUSES, DANS L'ORDRE
  1. DEPLOY N'A PAS ÉTÉ CLIQUÉ. Écrire la fonction dans l'éditeur ne la
     déploie pas. C'est la cause la plus fréquente.
  2. LE NOM N'EST PAS LE BON. « envoi-newsletter » exactement : pas
     d'underscore, pas de majuscule, pas d'espace au bout. L'admin
     appelle ce nom-là et aucun autre.
  3. CE N'EST PAS LE BON PROJET. Vérifiez que la référence affichée dans
     l'adresse du tableau de bord est bien lmwbwasupqkvswukieav.
  4. LE DÉPLOIEMENT A ÉCHOUÉ À LA COMPILATION. Edge Functions → la
     fonction → onglet Logs : l'erreur y est écrite.
  5. LES SECRETS MANQUENT. La fonction répond alors, mais l'envoi
     échoue. Le message d'erreur de l'admin le dit.


VÉRIFIER SANS RIEN ENVOYER
  L'écran Newsletter de l'administration interroge la fonction à chaque
  ouverture. Tant qu'elle manque, un bandeau orange s'affiche ; il
  disparaît tout seul dès qu'elle répond. C'est le signal le plus simple,
  et il ne coûte pas un e-mail.

  En ligne de commande :
      npx supabase functions list


ENSUITE
  Admin → Newsletter :
    1. Écrivez un sujet et un message.
    2. Mettez VOTRE adresse dans « M'envoyer un test » : seul vous
       recevez, avec [TEST] devant le sujet.
    3. Quand c'est bon : « Envoyer à tous ».

  Brevo en offre gratuite = 300 e-mails par jour. Au-delà de 300
  inscrits, l'envoi doit être étalé ou le compte passé en offre payante.
